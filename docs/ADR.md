Норма — `docs/BUILD_PIPELINE.md` | **новый** |
| ADR-026 | **Единственный поставляемый target рекомпиляции — Android arm64-v8a.** Рекомпилированный код под Windows не собирается, не линкуется и не поставляется. Windows-эталон — оригинальная лицензионная игра 1.27.1.7085 и её зафиксированные захваты; готовые `wc3_host27*.exe` старого дерева — исторические артефакты, не цели сборки. T1 = difftest против захватов без Windows-сборки; `--target windows` запрещён. Уточняет ADR-002/017/020; **уточнён ADR-027** в части верификационного target'а | **новый** |
| ADR-027 | **У T1 есть исполняемый DUT.** Вводится `--target headless`: `wc3_headless` собирается на CI-хосте (не Windows) из того же корпуса, HLE-реестра и `runtime/app`, что и Android-продукт, с `platform/headless` и `gfx/null` (канонический поток команд D3D9 вместо пикселей). Роли **O/G/H/D** зафиксированы в E1.1/V4.7; E3.6 сравнивает каденцию тиков с захватом G, а не с отсутствующим рекомпилированным Windows-хостом. ADR-026 **уточняется, не отменяется**: headless не входит в APK, не поставляется, `--target windows` остаётся запрещён. Норма — `docs/VERIFICATION.md` V4.7/V5.7/V5.8, `docs/BUILD_PIPELINE.md` BP-5.5/BP-7.2/BP-8.3. Реализация на 2026-11-06 = `missing` (G-09/G-13) | **новый, закрывает «T1 без исполнителя»** |
| ADR-028 | **Изменения сгенерированного C требуют исполнительного гейта.** Вводятся **G-15** (семантическая эквивалентность LiftPass) и **ABI-11**: эталон — Python-reference лифтер, сравниваются нормализованные тела функций, каждое изменение публикует function-level change set. Инварианты проверяются в генераторе (EmitPass) и пинятся `lift_rev`/`corpus.sha256`, а не регекс-линтом 2,4 ГБ C в T0. Порядок G-14 → G-15 → применение pass (V6.5). Число 82,93% зафиксировано как замер только `war3.exe` (10 860 из ~217 640 функций) и не может ранжировать pass'ы. Норма — `docs/GUEST_ABI.md` ABI-11, `docs/VERIFICATION.md` V2/V6.5/V9/V10, `docs/BUILD_PIPELINE.md` BP-6.4. Реализация = `missing` | **новый, закрывает «переписывание 42 713 сайтов без гейта»** |
| ADR-029 | **Game-first: гейты — диагностика, не блокер.** Статусы `G-xx` остаются фактическими и публикуются, но отсутствующий, красный или `unavailable` гейт больше не запрещает писать код, переносить HLE, линковать корпус, запускать устройство и выпускать локальные сборки. Отменяются блокирующие формулировки ADR-020/ADR-022 и производные «до закрытия G-xx нельзя». Acceptance-прогон может оставаться красным; это отчёт, а не запрет работы. Цель — исполняемая игра; точность и полное покрытие гейтами восстанавливаются после первого playable milestone. Норма — `docs/VERIFICATION.md` V1/V6, `docs/BUILD_PIPELINE.md` BP-3.5/BP-8.1 | **новый, приоритет владельца 2026-11-06** |
| ADR-030 | **Два варианта сборки и тегированная диагностика.** Поставляемый release имеет `applicationId` `wc3.recomp`, отладочный debug — `wc3.recomp.debug` (суффикс `applicationIdSuffix`), оба ставятся на устройство одновременно и не разделяют данные. Вариант — один атомарный вход `--variant`, задающий Gradle-задачу, native-сборку, `WC3_DEBUG` и каталоги; debug сохраняет оптимизированный native-код. Любая вводимая отладочная/логгирующая/трассирующая инструкция оборачивается в `#if WC3_DEBUG && WC3_DEBUG_<ЦЕЛЬ>` с тегом целевой подсистемы (`DEBUG_GRAPHICS` из постановки = `WC3_DEBUG_GRAPHICS`); реестр тегов — единый заголовок `runtime/diag/wc3_debug.h`. Диагностика не меняет замороженный guest ABI и наблюдательна. Третьего пакета и `WC3_DOGFOOD` как варианта нет. ADR-026/027/029 не отменяются: debug APK не поставляется, `--target windows` запрещён, гейты не блокируют. Норма — `docs/BUILD_VARIANTS.md` BV-1…BV-13, трассировка на G-01/G-12/G-13 без новых `G-xx`; реализация на 2026-11-07 = `missing` | **новый, приоритет владельца 2026-11-07** |
