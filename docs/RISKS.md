# Риски

Статус: **производный реестр** (2026-11-06). Вынесено из §12
`docs/ARCHITECTURE_1.27B.md` при M2; §12 в хабе оставлен указателем.
Приоритет при расхождении — `docs/README.md`. Меры приведены к гейтам
`docs/VERIFICATION.md` V2 и владельцам областей.

| Риск | Влияние | Мера |
|---|---|---|
| Гонки в guest-shared handle tables при реальных потоках | высокое | классификация состояния §3.1, per-object locks, debug assertion «dispatch под локом», T1 multithread-тесты |
| Регрессия при переносе ~20 000 строк рабочего runtime | высокое | strangler-cutover, T0 + T1 на каждом шаге, difftest-харнес из Step 0 |
| Гейт объявлен, но не проверяет инвариант (слабые флаги раннера, `not implemented`, отсутствующий oracle) | высокое | ADR-022, V1–V2: матрица статусов, запрет ослаблений в acceptance, V6.2 до закрытия G-08/G-09 запрещает M5 |
| **Дрейф headless-DUT от Android-продукта**: зелёный T1 подтверждает поведение модели, а не устройства | высокое | Один и тот же corpus/`wc3_hle_*`/`wc3_app_*` для обоих target'ов (V4.7.1), `--policy` доказывает отсутствие `platform/headless`/`gfx/null` в APK (BP-7.2), отчёт пинит хэши DUT (V5.7), T2 обязателен при DoD (V9), T1 не является свидетельством о DXVK-матрице (GB-7) |
| **Непроверенное преобразование сгенерированного C**: 42 713 сайтов переписываются без доказательства эквивалентности | высокое | G-15 / ABI-11 / ADR-028: golden-набор по каждому модулю, нормализованные тела против Python-reference лифтера, function-level change set, самопроверка V5.4, инварианты в генераторе (BP-6.4); Step 5b блокируется до G-14 и G-15 (V6.5) |
| Drift `argc`/callconv → сдвиг `esp`, падение через тысячи импортов | высокое | PE presence + call-site arity + `stack_cleanup` из одной формулы, `hle_abi_test` |
| Неполный набор MPQ / неверный путь данных на устройстве | высокое | `AssetApi`, явная диагностика на старте, T2 save/load |
| DXVK 3.1.1 не создаёт device на «1.3+» драйвере | высокое | На system Adreno 1.3 это **штатный**, а не исключительный путь (лог 2026-11-04). Fallback на 1.10.3, `dxvk_shim_reset()` и device matrix — GB-4/GB-5; до измерений ADR-004/007 `provisional` |
| Потеря Turnip/adrenotools при применении `--policy` | высокое | `VulkanDriverApi` разрешён явно; policy банит только внешние D3D-DLL |
| Неизвестная цель dispatch в релизе | высокое | coverage gate, probe-ledger до неподвижной точки, fatal вместо soft-unknown |
| Устройство недоступно | среднее | T0/T1 остаются зелёными, T2 = `unavailable`, проект не BLOCKED |
| Debug-код в release | среднее | `--release` по preprocessed output + бинарнику с allowlist |
| Legacy graphics paths просачиваются | среднее | `--policy` по link graph |
| 216 МБ `.so`: время загрузки, page cache | среднее | метрика размера, `--gc-sections`, без жёсткого бюджета |
| Регрессия исправленного поведения остаётся незамеченной: baseline снят до исправления | высокое | V6.6: владелец в V10, baseline-маркеры из O/G на исправленной сборке, инварианты V5.9 до переноса graphics/HLE-кода; E11 запрещает `pass` без них |
| **Оптимизации без измеримого контура**: 24 пункта лестницы принимаются по статическим числам одного файла | высокое | PM-1…PM-9: счётчики `WC3_PERF`, бюджет PM-2, замер по всем модулям PM-4, DAG PM-5, отчёт PM-8; G-10 = prerequisite (V6.7, владелец Step 0) |
| **Инвариант блокировок проверен только эвристически**: L0/L1 без графа вызовов и runtime-assertion | высокое | TA-3 (L2 = `missing`), TA-4 (стресс-тест E5.3 с ≥2 guest threads), TA-2 (контракт host-потока); G-01 остаётся `enforced` только для L0/L1 |
| **Лестница оптимизаций ранжирована по статике одного модуля**: 82,93% и 42 720 сайтов сняты с `war3.exe`, а стоимость сайта = сайты × частота | высокое | PM-17: каталог вместо ранжирования, взвешивание профилем PM-13, запрет обосновывать порядок внедрения статикой; ABI-11.6, PM-4 |
| **Замер неотделим от дрейфа железа**: одиночная пара A→B конфаундится прогревом, DVFS, page cache и термальным троттлингом | высокое | PM-19 (interleaved `ABBA` и парная статистика), PM-18 (атрибуция времени по доменам), PM-20 (бюджеты по фазам), PM-15/TA-18 (identity прогона) |
| **Сценарий корректности используется как нагрузочный**: V5.2 = 60 с простоя, игровой цикл почти не исполняется | высокое | PM-21 (`config/scenario.perf.json`, `scenario_sha256` в identity); без него G-10/G-11 = `unavailable`, не `pass` |
| **G-15 сравнивает сгенерированный C, а не поведение бинаря**: на машинном C с UB `-O0`/`-O2`/LTO могут разойтись | высокое | PM-23: golden-набор на двух уровнях `-O` плюс UBSan в T0; PM-22 — цена LTO на 2,4 ГБ корпуса |
| **T1 не видит гонок по времени**: V4.7.2 фиксирует планирование, TA-10 отдаёт jitter устройству, которого может не быть | высокое | TA-12 (набор детерминированных враждебных расписаний в headless-DUT), TA-13 (реентерабельность), TA-16 (summary корпуса для L2), TA-14 (остановка при INFINITE-wait) |
| **ADR-029 оставил блокирующие формулировки в производных документах**: V7/V10 и отдельные строки V2 всё ещё говорят «блокирует» | среднее | Rev 2.8 привёл к game-first только затрагиваемые строки; остальные перечислены как долг выверки в `BACKLOG.md` B5; `check_docs.py` проверяет сплошность `PM-n`/`TA-n` |
| **Параллельная правка дерева уже ломает T0**: во время Rev 2.8 в дерево добавлен `runtime/legacy/hle_android.c` (10 333 строки) — R4 и `--concurrency` падают на «unowned host lock» и `#ifdef WC3_DEBUG`; `platform_android.c` держит 2040 строк | высокое | B2/B5/B6, один владелец на файл, `check_docs.py --strict` и `check_arch.py --strict --concurrency --release` после каждой правки; V1.7 запрещает ослаблять гейт ради прохождения — исправляется **код**, а не порог R4 |
| **Карантина миграции не существует**: as-built код лежит в `runtime/legacy/` без манифеста, а новый `runtime/boot/dispatch_boot.c` уже включает оттуда `host.h`/`hle_android.h` | высокое | R15 (`QUARANTINE.md`, `expires_at`, `target_module` по H5), доступ только через `hle_legacy_shim` (H6.3/TA-1); R4-исключение — явная временная запись, а не поднятие лимита (V1.7) |
| **Направление зависимостей §4.3 ничем не проверяется**: `check_arch.py --policy` = `declared`, граф `#include` не строится | высокое | R16: `config/dep_matrix.json` + `tools/check_deps.py --strict` в T0, ребро вверх или `hle/abi` → OS-заголовок = error |
| **R-правила объявлены гейтами, но не проверяют**: R5 — no-op, R1 ловит не те имена файлов, R9/R10/R12/R14 дают warning, R4 для документов давал warning с текстом про закрытый M2 | высокое | R20 (матрица вердиктов `error`/`warn`/`review` в §3), R21 (маркеры generated), R22 (R4-overflow = error, near-limit ≥380); ADR-022 |
| **Два source root и продукты сборки вне `build/`**: `apps/android_gameactivity/` держит `app/src/main/java` и `src/main/cpp`, Gradle-кэш лежит в `apps/.../build/` | среднее | R17: один `src/main/` на модуль, все продукты в корневом `build/`, ad-hoc пути `.gitignore` переносятся в R2-allowlist |
| **Статус миграции — проза**: «M2 DONE», «0 errors» в §5 не привязаны к артефакту; при ADR-029 это уже неверно | среднее | R19: `config/migration.json` как пинящийся вход, `check_file_layout.py` запрещает `done` без `evidence` (F2) |
